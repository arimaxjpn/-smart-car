# Smart Car README

最終更新: 2026-03-08

## 概要

Smart Car は、iPhone から乗車/降車を記録し、Google スプレッドシートに保存する運転記録アプリです。

- フロントエンド: `index.html`
- バックエンド: `Code.gs` (Google Apps Script)
- 記録先: Google スプレッドシート `運転日誌`
- 写真保存: Google Drive
- OCR: Gemini API

## スプレッドシートの役割

このプロジェクトで一番重要なシートは `運転日誌` です。

- 乗車時の日時、位置、写真、OCR結果を保存
- 降車時の日時、位置、写真、OCR結果を保存
- 業務目的、走行距離、ステータスを管理
- 月次PDFの元データになる

## 月次PDFの仕様

- 対象は `運転日誌` シートの `closed` レコードのみ
- 判定月は `乗車日時` ではなく `降車日時` ベース
- PDFには画像を入れず、一覧と集計だけを出す
- 明細の出力項目は `日付 / 乗車住所 / 降車住所 / 開始値 / 終了値 / 走行km / 業務目的`
- 下部に `件数 / 合計走行km / 合計金額` を出す
- 合計金額は `走行km × 設定!B4` で計算する

### 要確認の扱い

- OCR未確定、開始値/終了値未確定、走行km未確定は `要確認`
- `終了値 < 開始値`、`走行km < 0`、`走行km > 500`、開始/終了値との差分不一致も `要確認`
- `要確認` は月報内の別一覧に出し、合計件数・合計走行km・合計金額には含めない

### 保存先とファイル名

- Drive保存先は、設定シート `B5` の写真フォルダ配下に作る `月報PDF` フォルダ
- ファイル名は `YYYY-MM_運転日報.pdf`
- 手動再出力時は同名の旧PDFをゴミ箱に移してから新しいPDFを保存する

### 出力タイミング

- 自動作成はこれまでどおり毎月1日に前月分を作る
- 手動再出力は `generateMonthlyPDF_(year, month)` を直接実行する

## スプレッドシートの確定レイアウト

現在の見た目は `applyJournalFormat()` で再適用できます。

### ヘッダー色

- 乗車エリア `A:H`: 青系
- 降車エリア `I:O`: 緑系
- 業務/状態エリア `P:S`: 茶系

### 表示形式

- 日時 `B / I`: `yyyy/MM/dd HH:mm`
- 緯度経度 `C / D / J / K`: 小数2桁
- OCR/開始値/終了値/走行km `G / H / N / O / Q`: `#,##0`

### 配置

- 緯度経度、OCR、開始値、終了値、走行km: 右寄せ
- 業務目的 `P`: 中央寄せ
- 住所 `E / L`: 左寄せ
- 写真URL `F / M`: 左寄せ

### 折り返し

- 折り返しあり: `E / L / P`
- それ以外は基本折り返しなし

### 条件付き書式

- `R=open`: 黄色系
- `R=closed`: 緑系
- `G / N`: OCR失敗っぽい値に警告色
- `Q`: 500km超で警告色

## スプレッドシート関連の重要関数

`Code.gs` にある、シート用の主な関数です。

- `setupSheets()`
  - 初回セットアップ
  - シート作成、設定シート作成、Drive フォルダ作成、トリガー設定
- `updateJournalHeaders()`
  - ヘッダー名だけ更新
  - データ本体や列順は変更しない
- `applyJournalFormat()`
  - 列幅、色、寄せ方、表示形式、条件付き書式を再適用
- `generateMonthlyPDF_(year, month)`
  - 前月または指定月の月報PDFを作成
  - `closed` / `降車日時ベース` / `要確認分離` で集計
- `migrateColumnOrder()`
  - 古い列構成から新しい列構成へ移行するための関数
  - 通常運用では何度も実行しない

## 安全な再適用手順

見た目を再現したいときは、次の順で実行します。

1. `updateJournalHeaders()`
2. `applyJournalFormat()`

これで、

- ヘッダー名
- ヘッダー色
- 列幅
- 右寄せ/中央寄せ/左寄せ
- 条件付き書式

を現在の完成形に戻せます。

## 注意

- ヘッダー名の更新は `updateJournalHeaders()` を使う
- 見た目調整は `applyJournalFormat()` を使う
- `setupSheets()` は初期化寄りの処理なので、既存運用中は慎重に使う
- `migrateColumnOrder()` は移行用なので、通常は再実行しない

## アプリ反映の考え方

- `Code.gs` のシート整形だけ変えたとき
  - Webアプリの再デプロイは不要
  - GAS 側のコードを更新して関数実行で反映
- `index.html` の画面を変えたとき
  - Webアプリの再デプロイが必要
